# punch v1 spec

This is the binding design for v1. Phase threads implement it; they do not
redesign it. If a phase finds the spec wrong or ambiguous, it picks the
simplest reading, does the work, and lists the question under "Spec questions"
in its PR description. Do not edit this file except to fix a statement the
phase proved wrong, and say so in the PR.

## 1. Product

`punch` is a terminal punch list across every project one person works on,
with coding agents as first-class users. One local SQLite store holds every
project. A card is a local task, a GitHub issue, or a GitHub pull request.

- **GitHub is the source of truth** for GitHub-owned fields: title, state,
  assignees, linked PR state, review decision. For GitHub cards the column is
  derived from those fields and never set by hand.
- **The local store owns local fields**: notes, priority, due date,
  dependencies, agent slot, ordering, archive flag. These never go to GitHub.
- **Basecamp is a mirror.** A project linked to a Basecamp card table has its
  cards moved to match. Basecamp is never read for state.
- **Agents use the same CLI as people**, with `--json`, stable refusal codes,
  and idempotent writes. MCP exposes the same operations.

## 2. Non-goals for v1

Do not build these, even partially: launching or supervising agents; git,
branch, worktree, or PR creation; Jira or any tracker other than GitHub and
Basecamp; a web UI; time tracking; WIP limits; checklists, threads or replies;
offline queues for GitHub writes; two-way merge of GitHub fields; editing
GitHub titles or bodies from punch; notifications; Windows support; plugin
systems; config beyond what this spec names.

## 3. Workspace layout

```
crates/punch-core/   library, no terminal deps
  src/store/         connection, migrations, queries
  src/model.rs       Project, Task, Column, Priority, AssigneeKind, Actor
  src/ops/           one module per operation; the only write path
  src/derive.rs      pure GitHub-state -> Column function
  src/github/        Gh trait, real `gh` adapter, fixtures in tests
  src/basecamp/      Basecamp trait, real `basecamp` CLI adapter
  src/error.rs       Refusal codes, PunchError
crates/punch/        binary `punch`
  src/cli/           clap definitions and text/JSON presenters
  src/tui/           ratatui board
  src/mcp/           stdio MCP server
  src/guide.md       agent skill text, embedded with include_str!
```

Rule: `cli`, `tui`, and `mcp` only call `punch_core::ops`. No SQL outside
`store`. No `gh` or `basecamp` process calls outside their adapter modules.

## 4. Store

- File: `$PUNCH_STATE_DIR/punch.db` if set, else `dirs::data_dir()/punch/punch.db`.
  Every test sets `PUNCH_STATE_DIR` to a temp dir. Nothing touches the real store
  in tests.
- Pragmas on open: `journal_mode=WAL`, `foreign_keys=ON`, `busy_timeout=5000`.
- Every mutating op runs in one `BEGIN IMMEDIATE` transaction. An op that would
  change nothing writes nothing and reports `changed: false`.
- `schema_version` table plus linear migrations in `store/migrations/NNNN_name.sql`,
  applied on open inside a transaction. Opening a store whose version is newer
  than the binary knows is refused with code `store-too-new`, exit 3.
- Migration ownership, to keep parallel phases from colliding: phase 1 owns
  `0001_init.sql` with the full v1 schema below. Phase 3 may add `0002_*`,
  phase 5 may add `0003_*`, only if they prove a column is missing. Others add none.

### Schema (0001)

```
projects(id INTEGER PK, slug TEXT UNIQUE NOT NULL,
         name TEXT NOT NULL, github_repo TEXT UNIQUE NULL,  -- "owner/name"
         sync_scope TEXT NOT NULL DEFAULT 'assigned' CHECK IN ('assigned','all'),
         archived INTEGER NOT NULL DEFAULT 0, created_at TEXT, updated_at TEXT)

tasks(id INTEGER PK,                       -- shown as t<id>
      project_id INTEGER NOT NULL REFERENCES projects,
      kind TEXT NOT NULL CHECK IN ('local','issue','pr'),
      gh_number INTEGER NULL,               -- required for issue/pr
      title TEXT NOT NULL, notes TEXT NOT NULL DEFAULT '',
      local_column TEXT NULL,               -- only for kind='local'
      priority INTEGER NOT NULL DEFAULT 2 CHECK BETWEEN 0 AND 3,
      due TEXT NULL,                        -- YYYY-MM-DD
      assignee TEXT NULL, assignee_kind TEXT NULL CHECK IN ('person','agent'),
      slot TEXT NULL,                       -- agent slot, e.g. keith-claude-2
      position REAL NOT NULL,               -- order within project
      archived INTEGER NOT NULL DEFAULT 0,
      revision INTEGER NOT NULL DEFAULT 1,  -- bumped on every change
      created_at TEXT, updated_at TEXT,
      UNIQUE(project_id, kind, gh_number))

task_after(task_id INTEGER REFERENCES tasks, after_id INTEGER REFERENCES tasks,
           PRIMARY KEY(task_id, after_id))

gh_cache(task_id INTEGER PK REFERENCES tasks,
         state TEXT NOT NULL,               -- OPEN | CLOSED | MERGED
         assignees TEXT NOT NULL,           -- JSON array of logins
         is_draft INTEGER NULL, review_decision TEXT NULL,
         linked_pr_number INTEGER NULL, linked_pr_state TEXT NULL,
         linked_pr_draft INTEGER NULL, linked_pr_review TEXT NULL,
         url TEXT NOT NULL, fetched_at TEXT NOT NULL)

basecamp_links(project_id INTEGER PK REFERENCES projects,
               bucket_id TEXT NOT NULL, card_table_id TEXT NOT NULL,
               column_map TEXT NOT NULL)   -- JSON {column: basecamp_column_id}

basecamp_cards(task_id INTEGER PK REFERENCES tasks, card_id TEXT NOT NULL,
               dirty INTEGER NOT NULL DEFAULT 0, last_error TEXT NULL)
```

Timestamps are UTC RFC 3339 strings. Use the `time` crate.

## 5. Columns

Fixed set, in board order:

| id | label |
|---|---|
| `todo` | Todo |
| `doing` | In progress |
| `review` | In review |
| `blocked` | Blocked |
| `done` | Done |
| `shipped` | Shipped |

Local cards store their column. GitHub cards compute it with `derive::column`,
a pure function of the `gh_cache` row, first match wins:

1. Issue CLOSED and linked PR MERGED, or a PR card MERGED: `shipped`.
2. Issue CLOSED, or PR card CLOSED unmerged: `done`.
3. An open PR (card or linked) with review decision CHANGES_REQUESTED: `doing`.
4. An open PR that is not draft: `review`.
5. An open PR that is draft: `doing`.
6. Issue OPEN with at least one assignee: `doing`.
7. Otherwise `todo`.

`blocked` is never derived. A GitHub card with unfinished dependencies is
still in its derived column, and `ready` excludes it (section 7).

## 6. Actors and agent rules

- The actor is an agent when `PUNCH_AGENT=<slot>` is set or `--as <slot>` is
  passed. Otherwise the actor is the person.
- Agents may: read anything, add tasks, append notes, set priority and due,
  set dependencies, move local cards among `todo`, `doing`, `review`,
  `blocked`, claim and unclaim, and run sync.
- Agents may not: move any card to `done` or `shipped` (refusal
  `agent-cannot-finish`), archive or unarchive (`agent-cannot-archive`), add or
  archive projects (`agent-cannot-manage-projects`), or link Basecamp.
- Enforce these in `punch_core::ops`, never only in docs or the CLI layer.
- GitHub cards cannot be moved by hand by anyone (`column-is-derived`).

## 7. Operations

Every op is a function in `punch_core::ops` taking an `Actor` and typed args,
returning `Result<Outcome<T>, PunchError>`. `Outcome` carries `changed: bool`,
the data, and `warnings` (used for Basecamp failures). The CLI and MCP map
these one to one.

Task references accept `t12`, `12`, or `<project-slug>#566` (GitHub number).
Unknown reference: `unknown-task`.

| op | CLI | notes |
|---|---|---|
| project_add | `punch project add <slug> [--name N] [--github owner/repo] [--scope assigned\|all]` | idempotent on slug with same fields; differing fields: `project-exists` |
| project_list | `punch project list` | |
| project_archive | `punch project archive <slug>` | |
| add | `punch add <title> -p <slug> [--notes] [--priority 0-3] [--due] [--after t1,t2] [--assignee X [--agent]]` | idempotent: same project + title + assignee among non-archived local cards returns the existing task with `existing: true` |
| add plan | `punch add --file <path\|->` | JSON array of add args; per-item `created`/`existing`/`failed`; all valid items in one transaction |
| list | `punch list [-p slug] [--column c] [--all]` | `--all` includes archived and done/shipped |
| show | `punch show <ref>` | includes derived column, deps, gh cache, basecamp card |
| ready | `punch ready [-p slug] [--limit N]` | cards in `todo` (local or derived), not archived, every `after` task in done/shipped; sorted priority, then due (nulls last), then position |
| move | `punch move <ref> <column>` | local cards only; refuses `after-not-done` when moving to `doing` with unfinished deps |
| edit | `punch edit <ref> [--title] [--notes] [--priority] [--due\|--clear-due] [--after ...\|--clear-after]` | `--title` refused on GitHub cards (`github-owned-field`) |
| note | `punch note <ref> <text>` | appends `\n[<UTC> <actor>] text`; not idempotent, say so in help |
| archive / unarchive | `punch archive <ref>` | |
| claim / unclaim | `punch claim <ref> [--slot S]` | phase 3; GitHub cards: `gh issue edit N --add-assignee @me` then refresh; local cards: set assignee and slot |
| sync | `punch sync [-p slug]` | phase 3 GitHub pull, then phase 5 Basecamp reconcile |
| bc link / status | `punch bc link -p slug --bucket ID --card-table ID --map todo=ID,doing=ID,...` | phase 5 |
| board | `punch` or `punch board` | phase 2 TUI |
| mcp | `punch mcp` | phase 4 |
| guide | `punch guide` | phase 4, prints the embedded skill |
| setup | `punch setup claude\|codex` | phase 4, prints the exact command to register the MCP server; changes nothing |

Dependency rules: `after` may not reference itself, a task in another
project, an unknown task, or create a cycle. Refusals: `after-self`,
`after-cross-project`, `unknown-task`, `after-cycle`.

## 8. Output contract

- Text by default. `--json` on every command prints exactly one JSON object
  on stdout and nothing else:
  - success: `{"ok":true,"changed":bool,"data":...,"warnings":[...]}`
  - refusal: `{"ok":false,"refusals":[{"code":"...","message":"...","ref":"..."}]}`
- Exit codes: `0` success (including no-op), `1` refusal (nothing changed for
  the refused items), `2` usage error (nothing changed), `3` storage or
  external-tool failure (a write may have happened; read back before retry).
- Refusal codes are kebab-case constants in `punch_core::error`, listed in
  `docs/refusal-codes.md`, and never renamed once released.
- Help text for every list/show command says "agents should pass --json".

## 9. GitHub (phase 3)

- All GitHub access goes through the `Gh` trait. The real adapter shells out
  to `gh` with `--json` or `gh api graphql`; auth is whatever `gh` has. No
  tokens in punch.
- `sync` for a project with `github_repo`:
  - `assigned` scope: open issues assigned to `@me`, open PRs authored by
    `@me`, plus every card already in the store for that repo (refreshed by
    number, so closed and merged items update).
  - `all` scope: every open issue and PR, plus existing cards.
  - Linked PR for an issue: the most recently updated open-or-merged PR whose
    closing references include the issue (GraphQL `closingIssuesReferences`).
    A PR that closes an issue already in the store is not added as its own card.
  - Upsert `tasks` (title from GitHub) and replace the `gh_cache` row.
- Network or `gh` failure during a write-through op: refusal `offline` or
  `gh-failed` with the `gh` stderr in the message; nothing local changes.
  During sync: exit 3, with the projects that did sync reported.
- Tests use the `Gh` trait with recorded JSON fixtures under
  `crates/punch-core/tests/fixtures/github/`, plus one test that runs the real
  adapter against a fake `gh` script on `PATH`.
- No writes to any real GitHub repository during development or tests.
  Read-only `gh` calls against public repos are fine for recording fixtures.

## 10. Basecamp (phase 5)

- All Basecamp access goes through the `Basecamp` trait. The real adapter
  shells out to the installed `basecamp` CLI (0.21.0 on the dev box; read its
  `--help`). Auth belongs to that CLI.
- Card title: `#<gh_number> · <slot> · <title>`, with the slot segment omitted
  when empty, and `#<number>` replaced by `t<id>` for local cards.
- After any op that changes a linked task's column, title, or slot, punch
  ensures a card exists in the mapped column with the right title. A Basecamp
  failure never fails the op: it becomes a warning `basecamp-failed`, sets
  `dirty=1` and `last_error`, and the next `sync` retries dirty cards.
- `sync` reconciles every non-archived task of a linked project after the
  GitHub pull. Archived tasks are left alone.
- Changing the Basecamp destination clears every card association, including archived tasks, because card IDs belong to the old table; archived tasks receive no remote calls.
- Columns without a mapping are skipped with a warning `basecamp-unmapped`.
- Tests use a fake implementation and a fake `basecamp` script on `PATH`. No
  writes to any real Basecamp project during development or tests.

## 11. MCP (phase 4)

- `punch mcp` runs a synchronous stdio JSON-RPC 2.0 server implementing
  `initialize`, `notifications/initialized`, `tools/list`, `tools/call`, and
  `ping`. Hand-rolled, no async runtime: three methods do not justify tokio
  and an SDK.
- One tool per op in section 7 except board, mcp, setup. Tool input schemas
  mirror the CLI flags. Results return the same JSON object as `--json`.
  Refusals are tool results with `isError: true`, not JSON-RPC errors.
- The actor for MCP calls is an agent. The slot comes from `PUNCH_AGENT`, or
  the `--as` flag on `punch mcp`, defaulting to `mcp`.
- A test asserts every MCP tool name maps to a CLI subcommand and the reverse
  for the ops listed.

## 12. TUI (phase 2)

- ratatui + crossterm. Six columns side by side; narrow terminals show the
  focused column plus neighbours. Header shows project filter and counts.
- Keys: `h/l` focus column, `j/k` focus card, `H/L` move card left/right
  (local cards; refused cards flash the refusal message), `Space`/`Backspace`
  next/previous column, `p` project picker (including "all"), `/` filter by
  text, `Enter` detail pane, `a` add card, `e` edit notes in `$EDITOR`,
  `P` cycle priority, `x` archive with confirm, `?` help, `q` quit.
- Detail pane: title, ref, project, column, priority, due, assignee/slot,
  deps with their columns, notes, GitHub URL and fetched time.
- Refresh: poll `PRAGMA data_version` once a second and reload on change, so
  CLI and agent writes show up live. Edits go through ops with the card's
  `revision`; a mismatch is refusal `stale` and the TUI reloads.
- A panic hook restores the terminal. The TUI module stays under 4,000 lines.
- Test the model/update logic without a terminal, and render snapshots with
  ratatui's `TestBackend`.

## 13. Engineering rules

- Write the test first for each behaviour (red, green, refactor). Every bug
  fix lands with a test that fails without it.
- `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  and `cargo test --workspace` pass before a PR is marked ready.
- Allowed dependencies: clap (derive), rusqlite (bundled), serde, serde_json,
  thiserror, time, dirs, ratatui, crossterm; dev: assert_cmd, predicates,
  tempfile. Anything else needs a one-line reason in the PR description.
- No `unwrap`/`expect` in non-test code unless the invariant is commented.
- Brief comments on modules and non-obvious constraints. No speculative
  abstractions: a trait exists only where a fake is needed in tests (Gh,
  Basecamp).
- Update README usage and `docs/refusal-codes.md` in the same PR as the
  behaviour.

## 14. Phases

Stacked PRs. Each phase is one branch and one PR. Merge order 1, 2, 3, 4, 5.

| phase | branch | base | scope |
|---|---|---|---|
| 1 | `phase-1-core-cli` | `main` | store, schema 0001, model, ops for local cards, agent rules, CLI with JSON and exit codes, add plans, ready, deps |
| 2 | `phase-2-tui` | `phase-1-core-cli` | section 12 |
| 3 | `phase-3-github` | `phase-1-core-cli` | section 9, project `--github`, claim/unclaim, sync |
| 4 | `phase-4-mcp` | `phase-3-github` | section 11, guide, setup |
| 5 | `phase-5-basecamp` | `phase-3-github` | section 10, bc link/status, sync reconcile |
| 6 | after merges | `main` | release workflow, binaries, tap; not part of this run |

Phases sharing a base touch disjoint modules. Where they must touch shared
files (the clap command enum, `ops/mod.rs`, README), add only their own lines
so the later rebase is mechanical.
